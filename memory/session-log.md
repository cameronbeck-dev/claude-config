## 2026-05-09 — personal-llm (C:\Users\GGPC\Documents\programming\personal-llm) — first-message lag fix
User reported a noticeable lag on the very first message of a new conversation: input stayed populated for a couple of seconds before clearing and the message bubble appeared. Subsequent messages were instant. Root cause was in Chat.tsx handleSend: setInputText('') and addMessage() ran AFTER `await createConversation()` AND `await setActive(newId)` (which itself fetched /api/conversations/:id for a brand-new empty conversation). Two-stage fix: (1) hoisted setInputText('') above the awaits and replaced setActive with a direct setState (skips the wasted fetch on a known-empty conversation); (2) when user wanted seamless behaviour, went full optimistic — sync-prepend a placeholder Conversation with a `temp-${uuid}` id and the first 50 chars of the message as a provisional title, sync-add user + thinking bubbles, start spinner, THEN await createConversation in the background and reconcile by filtering the temp out (createConversation already prepends the real one) and rewriting message conversationIds from temp→real. Failure rolls back: filter the placeholder, clear active state, show error. The provisional title is replaced when the SSE 'title' chunk arrives with the LLM-generated short title. Initial reconcile-by-map produced duplicate sidebar rows because the store's createConversation already prepended the real convo — fixed by switching to filter. Server's previousId param is accepted but unused inside chatStream, so the temp id leaking into previousConversationId during the await is harmless. Committed and pushed as 7adbc33.

UI polish in the same commit: dropped the top-of-transcript "Session cost:" banner (users don't scroll up to read it), and replaced the bare per-message dollar amount with a whisper-styled footer line (`this reply cost $0.0003 · session running $0.0042`) — 11px italic, muted color, 2px left rule, matches the existing whisper visual language.
